## 2. 로그인 흐름 변경 — 이메일 인증번호(OTP)

### 2-1. 단계별 화면

| 단계 | 화면 | 버튼 |
|---|---|---|
| ① 최초 진입 | 아이디 · 비밀번호 입력 | **`인증번호 받기`** (로그인 버튼 없음) |
| ② 인증번호 받기 클릭 | 아이디 · 비밀번호 확인 → **아이디(이메일)로 인증번호 6자리 발송** → 비밀번호 아래에 인증번호 입력칸 노출 | `인증번호 받기` 가 **`로그인`** 으로 바뀜 |
| ③ 로그인 클릭 | 인증번호 확인 → 로그인 완료, 메인 이동 | — |

- 인증번호는 **아이디로 쓰는 이메일 주소**로 발송합니다. 별도로 이메일을 입력받지 않습니다.
- 입력칸 아래에 발송한 주소를 마스킹해 안내합니다.
  > `us****@example.com` 로 인증번호를 보냈습니다. 메일이 보이지 않으면 스팸함을 확인해 주세요.

### 2-2. 인증번호 입력칸

- 숫자만, 최대 6자리
- 입력칸 오른쪽에 **유효시간 3:00 카운트다운**
- 옆에 **`재전송`** 버튼 — 새 인증번호를 보내고 이전 번호는 무효 처리, 입력값·오류 문구·시도 횟수 초기화, 타이머 3:00 재시작

### 2-3. 인증번호 오류 처리

| 상황 | 문구 | 처리 |
|---|---|---|
| 6자리 미만 | 인증번호 6자리를 입력해주세요. | — |
| 불일치 | 인증번호가 일치하지 않습니다. (n/5회) | 시도 횟수 표시 |
| 5회 불일치 | 인증번호를 5회 잘못 입력했습니다. 재전송 후 다시 시도해주세요. | 입력칸 · 로그인 버튼 비활성, **재전송해야 재시도 가능** |
| 유효시간 만료 | 인증번호 유효시간이 만료되었습니다. 재전송 후 다시 입력해주세요. | 위와 동일하게 비활성 |

### 2-4. 아이디·비밀번호를 고친 경우

인증번호를 받은 뒤 아이디나 비밀번호를 수정하면 **받은 인증번호는 무효**가 되고 ① 최초 화면(인증번호 입력칸 숨김, `인증번호 받기` 버튼)으로 돌아갑니다.

## 3. 기존 로그인 제한은 `인증번호 받기` 단계에서 처리

아래 기존 처리는 그대로 유지하되, **`인증번호 받기`를 누르는 시점**에 수행합니다. 통과하지 못하면 인증번호를 발송하지 않습니다.

- 아이디·비밀번호 빈 값 검증
- 계정 제재(영구정지 · 일시정지) 안내 모달
- 비밀번호 실패 횟수 제한 (보안심사 3.4-④)
  - 1~2회: 아이디 또는 비밀번호가 일치하지 않습니다.
  - 3회부터: (n/5회) n회 더 실패하면 계정이 30분간 잠깁니다.
  - 5회: 계정 잠금 모달(잠금 해제까지 30:00 카운트다운), `인증번호 받기` 버튼 비활성
  - **변경: 잠금 시간 10분 → 30분** (경고 문구 · 잠금 모달 · 서버 잠금 시간 모두)

---

## 4. 기존 알림톡 2차 인증 제거

지금은 비밀번호 확인 후 **카카오톡 알림톡 2차 인증 모달**이 뜹니다. 이메일 인증번호로 대체되므로 **로그인에서는 알림톡 2차 인증을 제거**합니다. 두 가지를 모두 거치면 인증이 두 번이 됩니다.

> 발송 화면 등 다른 곳에서 쓰는 알림톡 인증은 이번 변경과 무관합니다.

## API (제안)

| 시점 | API | 비고 |
|---|---|---|
| 인증번호 받기 | `POST /api/auth/login` → `POST /api/auth/mfa/email/send` | 비밀번호 확인 통과 시에만 발송. 응답에 실패 횟수·잠금 상태 포함 |
| 재전송 | `POST /api/auth/mfa/email/send` | 이전 인증번호 무효화 |
| 로그인 | `POST /api/auth/mfa/email/verify` | 유효시간 3분, 5회 초과 시 해당 인증번호 폐기 |

- 유효시간 · 시도 횟수는 **서버 기준으로 검증**해 주세요. 화면의 타이머와 횟수 표시는 안내용입니다.
- 인증번호 메일 제목·본문 양식은 별도로 전달드리겠습니다.
