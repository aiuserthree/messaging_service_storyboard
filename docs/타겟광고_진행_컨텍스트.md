## 1. 서비스 한 줄 설명과 세 주체

> 톡벨 고객(주로 분양 현장 광고주)이 통신사·카드사·멤버십 등 매체의 수신 동의 고객 가운데 연령·지역 조건에 맞는 사람에게 광고 문자를 보내도록, 톡벨이 신청·결제·안내를 맡고 CJ올리브네트웍스 CROOVY(크루비)가 대상 추출·발송·리포트를 맡는 서비스입니다.

| 주체 | 하는 일 |
|---|---|
| 고객 | 신청서 작성, 견적 확인·결제, 문구 확정, 테스트 발송본 최종 확인, 리포트 확인 |
| 톡벨 | 고객의 유일한 창구. 접수·검사, CJ 전달, 회신 확인, 견적 승인, 결제, 문구·테스트 중계, 리포트 등록, 정산 |
| 크루비 (CJ 대행) | 대상(모수) 추출과 확대, 문구 검토·수정, 부킹, 테스트 발송, 발송, 리포트 |

- CJ는 고객과 직접 소통하지 않습니다. 모든 내용은 톡벨을 거칩니다.
- 톡벨과 CJ의 주 소통 창구는 Slack(그리고 카카오톡)입니다.
- 발신은 매체 명의로 나가고, 광고주 문의 번호는 본문에 넣습니다.
- 톡벨 직원이 상담하지 않는 것이 원칙입니다. 대신 사람이 확인해야 하는 곳(회신 값, 견적 승인 등)은 운영이 안정될 때까지 관리자가 맡습니다.

## 2. 신청 한 건 흐름 (10단계)

표기: **톡벨 자동** = 시스템이 처리, **톡벨 수동** = 관리자가 직접 처리. 정산은 후불(11/24 결정).

| # | 단계 | 주체 순서 |
|---|---|---|
| 1 | 신청 | 고객 신청서 작성 → 톡벨 자동 검사·접수 안내 |
| 2 | 대상 확인 | 톡벨 자동 Slack으로 요청 → 크루비 대상 추출 (부족하면 확대) |
| 3 | 회신 | 크루비 건수·금액·일정 회신 → 톡벨 수동 회신 숫자 확인 |
| 4 | 견적 | 톡벨 자동 판매가 계산 → 톡벨 수동 견적 승인 → 고객 견적 확인 |
| 5 | 결제 | 고객 결제 → 톡벨 자동 결제 승인 전달 → 크루비 부킹 |
| 6 | 문구 확정 (D-7까지) | 크루비 수정 문구 → 톡벨 자동 화면에 채움 → 톡벨 수동 확인 후 고객 전달 → 고객 확인·수정 요청 → 톡벨 자동 크루비 전달 → 크루비 반영 |
| 7 | 테스트 (D-1~2) | 크루비 캡처·원문 전송 → 톡벨 자동 화면에 채움 → 톡벨 수동 확인 후 고객 전달 → 고객 최종 확인 → 톡벨 자동 크루비 전달 |
| 8 | 발송 | 크루비 발송·완료 알림 → 톡벨 수동 상태 변경 |
| 9 | 리포트 | 크루비 리포트 엑셀 → 톡벨 수동 엑셀 업로드 → 톡벨 자동 읽기·고객 알림 → 고객 결과 확인 |
| 10 | 정산 (매달) | 크루비 정산서 발행 → 톡벨 수동 광고비 지급·수수료 계산서 → 크루비 수수료 지급 |

단계별 보충:

- **1 신청**: 신청 양식은 CJ 모수 확인 양식 항목만 받습니다 — 매체(하나), 현장명·캠페인명, 연령·지역, 대상이 모자랄 때 넓히는 범위, 발송 희망일 1~3순위, 희망 발송 시각 1·2순위(30분 단위), 발송 건수, 제목·문구. 자동 검사는 필수값, 매체별 최소 건수, 발송 시각(08~21시 안) 입니다.
- **2 대상 확인**: 넓힐 범위·순서와 먼저 넓힐 쪽(지역/연령)도 함께 보냅니다. 전송이 실패하면 관리자가 다시 보냅니다.
- **3 회신**: AI가 회신의 숫자를 읽어 참고값으로 보여 주고, 관리자가 값과 확대 적용 여부·최종 대상 조건을 확정합니다. 확정 전에는 견적에 쓰지 않습니다.
- **4 견적**: 관리자는 신청 건수·CJ 금액·결제 금액을 대조하고, 넓혔다면 신청 때 받은 범위 안인지 본 뒤 승인합니다. 승인해야 고객에게 보입니다. 고객은 최종 대상 조건(넓힌 조건 포함)·건수·일정을 확인 체크해야 결제할 수 있습니다.
- **5 결제**: 톡벨 기존 결제수단(신용카드·가상계좌·전용계좌)으로 견적 금액만 결제합니다. 결제 뒤에는 추가 검수 없이 CJ에 자동 전달합니다.
- **6·7 반자동 (11/24)**: 신청 건마다 Slack 스레드를 두고, 크루비가 그 스레드에 답하면 시스템이 관리자 화면에 채웁니다. 관리자는 확인 후 [고객에게 보내기]만 누릅니다. 자동으로 못 가져오면 관리자가 직접 붙여 넣거나 올립니다.
- **7 테스트**: 고객 휴대폰으로 테스트 문자를 받는 방식이 아닙니다. CJ가 보낸 문구 캡처와 원문을 고객이 마이페이지에서 보고, 확정한 문구가 그대로 나갔는지 최종 확인합니다.
- **시작 전 1회**: 이용신청서(후불 양식, CJ 확인 필요)에 정보 기입·날인 후 스캔본 전달, 보증보험 증권 제출(기준은 CJ와 협의).

## 3. 기한과 예외

### 기한 (D-n = 발송일 n일 전)

| 기한 | 내용 | 알림 |
|---|---|---|
| D-7 | 고객 문구 확정·수정 요청 마감. 확정 뒤에는 오타만 수정 | 미확정이면 확인함 「D-7 문구 확정」 자동 알림 |
| D-4~5 | CJ가 수정 사항을 반영할 수 있는 한도 (D-7 마감은 이보다 앞) | — |
| D-1~2 | 테스트 발송본(캡처·원문) 도착 — 문구 확정 후 늦어도 이때까지 | 따로 알림 없음 |
| 발송일 | 확정 발송일이 지났는데 처리가 안 되면 | 발송 처리 지연 자동 알림 |
| 발송 후 영업일 4일 | 리포트 전달 기한 | 리포트가 없으면 자동 알림 |

### 예외

| 경우 | 처리 |
|---|---|
| 결제 전 취소 | 고객이 직접 취소, 비용 없음 |
| 결제 후 취소 | 원칙상 받지 않음. 예외 요청은 매체별 위약금 기준으로 관리자가 수기 처리. 신청 전에 고지하고 동의를 받음 |
| 반려 | 별도 반려 코드 없음. CJ가 매체 가이드에 맞춰 고친 문구를 주면 고객이 확인(6단계). 반려 사유는 관리자가 직접 입력 |
| 대상 부족 | 고객이 신청 때 준 우선순위(지역 순서, 연령 부족 시 범위, 먼저 넓힐 쪽)대로 CJ가 확대. 넓힌 조건·건수는 견적에서 고객이 확인한 뒤 부킹 |
| 테스트에서 오류 발견 | 고객이 [수정 요청] → 관리자가 고칠 수 있는지 CJ에 확인해 알림 (가능 여부는 CJ 확인 필요) |

각 화면의 '화면설계 보기' 버튼을 누르면 항목별 설명이 나옵니다. 고객 화면 [신청 상세]는 맨 위 '설계 보기용 상태 전환'으로 단계별 상태를 볼 수 있습니다.
